# Rendering and animation research

Purpose: select the smallest technology change that enables the desired quality without replacing proven mathematical behavior. Sources accessed 2026-11-02. Recommendations below are engineering judgments for this repository, not vendor performance guarantees.

## Decision

Retain **Phaser 3.90 + Arcade Physics + React**, use built-in atlases/animations/tweens/particles, and CSS for DOM motion. Art quality, frame production, wall composition and visual hierarchy are the current limiting factors. No new runtime dependency is recommended for Phase 1 or 2.

## Maintenance and version findings

- Installed Phaser is 3.90.0. The official [release list](https://github.com/phaserjs/phaser/releases) currently marks **4.2.1 (9 July 2026)** latest; the project is active. This does not establish a continuing support guarantee for the 3.x line. Keep current lockfile for the visual project and evaluate major-version maintenance separately.
- Unversioned Phaser API pages inspected identified **4.1.0 API documentation**. Therefore examples and API names must be checked against the repository's installed source or [tagged 3.90 AnimationManager](https://github.com/phaserjs/phaser/blob/v3.90.0/src/animations/AnimationManager.js), [FX component](https://github.com/phaserjs/phaser/blob/v3.90.0/src/gameobjects/components/FX.js), and [TileSprite](https://github.com/phaserjs/phaser/blob/v3.90.0/src/gameobjects/tilesprite/TileSprite.js). No new API recommendation relies solely on latest-version docs.
- Pixi's official [version page](https://pixijs.com/versions) displayed 8.21.0 as its stable documentation target when inspected; its [release stream](https://github.com/pixijs/pixijs/releases) demonstrates active development. Treat this as a documentation snapshot, not a pinned recommendation or guarantee of latest npm patch. [Architecture](https://pixijs.com/8.x/guides/concepts/architecture) describes its renderer, ticker, assets and scene graph; those overlap AngleMaze's already installed Phaser facilities.
- GSAP has maintained [installation/ES module documentation](https://gsap.com/docs/v3/Installation/) and [matchMedia cleanup/reduced-motion guidance](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/). No GSAP version is selected because no addition is recommended. Its free-use change was announced by [Webflow in April 2025](https://webflow.com/updates/gsap-becomes-free); inspect current license, rather than relying on older paid-plugin advice.

## License evidence

Phaser's [tagged MIT license](https://github.com/phaserjs/phaser/blob/v3.90.0/LICENSE.md) and installed package both identify MIT. Pixi's [official MIT license](https://github.com/pixijs/pixijs/blob/dev/LICENSE) similarly permits use subject to its notice conditions. GSAP's [current Standard No Charge license](https://gsap.com/community/standard-license/) permits ordinary websites/web applications and has restrictions concerning competing visual animation builder products; it is not interchangeable with MIT. No proposed AngleMaze feature is such an editor. This is a scope assessment, not legal advice. Asset/font provenance remains separate from engine licensing.

## Decisions and exclusions

Use atlas JSON/PNG export from a suitable art workflow; no runtime atlas packer is needed. Selection of a commercial art/packing tool is pending the owner's workflow/budget and is not required to start static exports. No skeletal animation plugin, Spine runtime, GSAP, Pixi, physics library or shader package is required. Frame animation gives the memorial character precise control over asymmetric anatomy without adding a rig/runtime licensing dependency.

## Visual rejection update — 2026-11-03

The owner reported that successive grass/wall asset swaps still looked flat and that the added wall extrusion, highlights and square join blocks looked awkward in the actual level. The shared failure was treating depth as more painted strips plus overlapping geometry. That wall treatment has been removed. Keep one continuous wall strip with its own authored bevel/shading and a single restrained shadow until a proper modular cap/corner/T-junction set is ready.

For the next major visual pass, prioritize art-authored height/normal maps and one coherent light direction. Phaser Light2D is the most relevant built-in renderer feature, but it is WebGL-only and requires paired normal maps. Pilot it against the current renderer and retain baked lighting for Canvas fallback. Normal maps must be authored and reviewed with the same reference style; generic normals or shader glow are not substitutes for sculpted art. Check depth ordering and shadow silhouettes at the game's actual 800×600 world scale before adding effects.

Reassess only if a measured limitation remains after the proposed static scene and animation work. Any engine migration must include a separate measured comparison and regression plan. Acceptance budgets are proposals in [the roadmap](05-implementation-roadmap.md), not claims derived from vendor demos.

## Supplied reference-art implementation follow-up — 2026-11-03

The owner selected the supplied checkpoint-state sheet and `wallsNew.png` after rejecting generated wall effects. The implementation now uses Phaser 3.90 named texture frames and a static `RenderTexture`; a one-time browser Canvas transform aligns the diagonal sprite so its length and 28px thickness can scale independently. The source's overlapping elbow crop was narrowed after a rendered debug pass revealed the neighboring corner pixels were widening the alpha bounds. The supplied elbow artwork is placed at shared, two-segment right-angle nodes. The sheet does not include a dedicated T-junction sprite, so degree-three joins still require review. Checkpoint badges are cropped from the supplied sheet and the pale-blue presentation background is keyed out in Canvas.

This is use of the installed Phaser renderer and browser Canvas, not an engine/library migration. The official [Phaser texture-frame API](https://docs.phaser.io/phaser/concepts/textures) and [RenderTexture guide](https://docs.phaser.io/phaser/concepts/gameobjects/render-texture) are the relevant renderer sources. Both level captures are stored in [reference kit evidence](evidence/walls-checkpoints-first-review/); they were captured through headless Chrome's Canvas renderer. WebGL `Light2D`, fractional-scale joins and mobile performance still need manual browser review. The source sheet includes baked shadows, so the composed walls intentionally do not receive an additional dark outline or shadow pass.
